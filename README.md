# DNF Census, 던파 캐릭터 표본조사

던전앤파이터 캐릭터를 표본조사 방법론으로 조사하고, 그 방법이 무엇을 놓치는지까지
같이 재서 공개한 리포트입니다.

**리포트**: https://dnf-census.vercel.app

![한눈에 보기 화면](docs/captures/desktop-overview.png)

> 이 조사는 모집단 추정이 아니라 표본조사 방법론의 시연입니다. 표본을 어떻게 뽑았고
> 그 표본이 어디로 기울었는지를 끝까지 드러내는 것이 목적입니다.

---

## 무엇을 조사했나

캐릭터의 직업, 성장 단계, 접속 기록을 서버 8곳에서 모아 집계했습니다. 같은 것을 세
가지 방법으로 조사해 서로 대조했습니다.

| 방법 | 표본 | 무엇을 보나 |
| --- | --- | --- |
| 이름 검색 (2차 회차) | 1,301,990명 | 이름에 특정 두 글자가 든 캐릭터. 저레벨과 오래 쉰 캐릭터까지 본다 |
| 이름 검색 (1차 회차) | 31,523명 | 같은 방법, 시드 36개 |
| 명성 점수 훑기 | 18,552명 | 레벨 110 이상이면서 최근 90일 안에 접속한 캐릭터만 본다 |

1차 조사일 2026년 8월 26일, 2차 집계일 2026년 8월 31일.

---

## 무엇을 찾았나

### 검색 상한은 낮은 성장 단계 캐릭터를 먼저 걸러낸다

한 번에 200명까지만 돌려주는 검색이 무엇을 가리는지 재려고, 상한에 걸린 조합 400개를
직업군으로 쪼개 다시 불렀습니다. 평균 682명이 나왔습니다. 3.41배입니다. 새로 드러난
캐릭터의 87.2%가 가장 낮은 성장 단계에 있었습니다.
[자세히](docs/findings.md#31-검색-상한은-낮은-성장-단계-캐릭터를-먼저-걸러낸다)

### 실제 인구는 화면에 보이는 것보다 아래쪽이 두껍다

레기온 입장 전 구간은 관측값이 48.78%인데, 상한을 보정하면 68.49%가 됩니다.
[자세히](docs/findings.md#32-실제-인구는-관측값보다-아래쪽이-훨씬-두껍다)

### 이름 짓는 습관이 표집을 왜곡한다

바람이라는 두 글자로 걸린 캐릭터 38명 가운데 24명이 스위프트 마스터였습니다. 어둠은
다크 랜서로, 붉은은 버서커로 이어졌습니다. 낱말과 직업이 맞물립니다.
[자세히](docs/findings.md#33-이름-짓는-습관이-표집을-왜곡한다)

### 시드를 무엇으로 고르는지가 개수보다 열 배 중요하다

1차가 쓴 36개의 커버리지는 1.21%였습니다. 같은 개수를 흔한 조합으로 골랐다면
13.11%였습니다. 1,000개로 늘려 50.66%가 됐습니다.
[자세히](docs/findings.md#34-시드를-무엇으로-고르는지가-개수보다-열-배-중요하다)

## 무엇이 틀렸고 어떻게 고쳤나

| 항목 | 1차 | 2차 |
| --- | --- | --- |
| 시드 | 36개 (절반은 일부러 드문 조합) | 1,000개 (흔한 조합 위주) |
| 커버리지 | 1.21% | 50.66% |
| 표본 | 31,523명 | 1,301,990명 |
| 직업 구성 차이 | 9.54%포인트 | 5.24%포인트 |
| 상한 도달률 | 45.8% | 90.5% |

직업 축은 좋아졌습니다. 상한 도달률은 나빠졌습니다. 흔한 조합을 쓰면 더 많은
캐릭터에 닿지만 거의 모든 검색이 상한에 걸리기 때문입니다. 둘은 맞바꾸는 관계입니다.

1차 결과는 하나도 고치지 않고 그대로 두었습니다. 두 회차를 나란히 보관합니다.

---

## 이 조사에서 배운 것

네 가지 모두 처음 판단이 틀렸던 것들입니다.

- **직업군으로 쪼개도 상한을 못 벗어날 것으로 봤습니다.** 실제로 쪼갠 뒤 상한에 걸린
  비율은 5.2%였습니다.
- **명성 점수 방식을 정답지로 삼으려 했습니다.** 그 방식도 레벨 110 미만과 오래 쉰
  캐릭터를 못 봅니다. 상한을 걷어낼수록 오히려 멀어집니다.
- **1차 설계에서 커버리지 손실을 계산하지 않았습니다.** 상한을 피하는 효과만 보고
  드문 조합을 절반 넣었는데, 그 선택이 커버리지를 열 배 깎았습니다.
- **직업 기준을 성장 완료로 좁히면 검색 방식 차이가 거의 사라진다고 적었습니다.**
  다시 재 보니 15.48에서 13.31%포인트로 줄어든 정도입니다. 사령술사처럼 차이가
  사라지는 직업도 있었으나(2.56배에서 1.16배) 스위프트 마스터는 5.14배에서 4.92배로
  거의 그대로 남았습니다. 예시 두 개만 보고 일반화한 것이라 정정합니다.

[전부 보기](docs/findings.md#4-틀렸던-예측과-판단)

---

## 관측 한계

- **레벨 110 미만을 이름 없이 조회할 방법이 없습니다.** 레벨 범위를 넣어도 조용히
  무시됩니다. 영문과 숫자 시드로도 열리지 않습니다.
- **접속만 하고 기록을 남기지 않는 캐릭터를 가릴 수 없습니다.** 활성도는 행동 기록으로
  판정하므로 낮은 성장 단계에서 조용한 쪽으로 부풀 수 있습니다.
- **명성 점수 방식은 레벨 110 미만, 90일 넘게 미접속, 명성 점수가 없는 캐릭터를 못
  봅니다.**

[자세히](docs/findings.md#5-관측-한계)

## 어떻게 만들었나

```
pipeline/            # Python 파이프라인
  api_client.py      # Neople API 클라이언트 (0.3초 대기, 재시도 1회)
  sample.py          # 시드 검색으로 표본 프레임 (체크포인트 재개)
  timeline.py        # 층화 서브샘플로 활성도 판정
  aggregate.py       # 집계, 마스킹, 식별 정보 폐기 검증
  insights.py        # AI 인사이트 (배치 1회)
config/              # 시드, 명성 구간, 활성 기준, 직업 정규화 맵
data/                # 집계 결과 (식별 정보 없음), 편향 노트, 회차별 산출물
docs/findings.md     # 발견과 실측치를 모은 문서
report/              # Vite + React 7화면 리포트
scripts/             # 회차 수집, 검증, 대조, 스캔 스크립트
```

회차는 파일명과 `meta.round`로 구분합니다. 1차는 `census_2026-08.json`,
2차는 `census_2026-08-r2.json`입니다. 각 파일이 무엇인지는
[data/README.md](data/README.md)에 한 줄씩 적어 두었습니다.

### 재현

```bash
# .env에 NEOPLE_API_KEY (인사이트는 ANTHROPIC_API_KEY 추가)
python -m venv .venv && .venv/Scripts/pip install requests python-dotenv tzdata anthropic

# 1차 회차
python pipeline/sample.py             # 표본 수집 (약 290콜, 90초)
python pipeline/timeline.py           # 활성도 조사 (600콜, 3분)
python pipeline/aggregate.py          # 집계
python scripts/purge_ids.py           # 식별 정보 폐기와 스캔

# 검증용 명성 방식
python scripts/fame_survey2.py        # 명성 축 계통표집 (947콜, 5분)
python scripts/fame_analyze.py        # 1차와 대조
python scripts/build_verification.py  # 리포트가 읽을 대조표

# 2차 회차
python scripts/build_seeds_r2.py      # 시드 1,000개 (867콜, 5분)
python scripts/sample_r2.py phase1    # 표본 수집 (8,000콜, 41분)
python scripts/phase2_sample.py       # 상한 우회 표본 (7,200콜, 36분)
python scripts/timeline_r2.py         # 활성도 서브샘플 (660콜, 3분)
python scripts/aggregate_r2.py        # 집계
python scripts/cap_correct.py         # 상한 보정 추정
python scripts/compare_r2.py          # 세 방법 대조
python scripts/verify_findings.py     # 문서 수치와 데이터 대조

# 리포트
cd report && npm install && npm run build
node scripts/font-check.mjs           # 세리프 글자가 폴백으로 안 떨어지는지
node scripts/stability.mjs            # 표시 안정성
cd .. && python scripts/verify_final.py
```

빌드 직전에 집계 파일을 읽어 내부 키 이름과 내부 용어를 화면 용어로 바꾼 사본을
만듭니다. 원본 집계 파일은 바꾸지 않습니다.

## 데이터 윤리 원칙

- 캐릭터명, 모험단명, 길드명은 **수집하지도 저장하지도 않습니다**. 이름을 판정에 써야
  하는 계산은 메모리 안에서만 하고 결과 수치만 남깁니다.
- 캐릭터 식별자는 받는 즉시 되돌릴 수 없는 형태로 바꿉니다. 커밋되는 어떤 파일에도
  식별 정보가 없습니다 (자동 스캔 0건 통과).
- 특정 캐릭터를 지목하는 서술을 하지 않습니다. 표본 10명 미만 칸은 공개하지 않습니다.
- 요청 예절을 지킵니다. 호출 사이 0.3초를 쉬고 재시도는 한 번까지만 하며, 상시로
  돌리지 않고 회차 단위로만 모았습니다.
- 총 호출량과 모델 비용을 실측으로 공개합니다.
