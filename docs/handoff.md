## 성능 작업 기록

### 무엇을 찾았나

- 스크롤과 클릭 구간은 CPU 4배와 6배 저속 조건에서 모두 0밀리초입니다. 문제 없습니다.
- 문제는 **화면 진입 구간의 메인 스레드 블록** 한 곳입니다.
- 가장 컸던 자바스크립트 비용은 Anime.js의 `updateBounds`였습니다. 등장 연출마다
  스크롤 관찰자를 따로 만들어, 진입할 때 그 전부가 한꺼번에 위치를 재고 있었습니다.

### 무엇을 고쳤나

- 화면 일곱 개를 한 덩어리로 묶던 것을 갈랐습니다. 첫 화면만 처음부터 들고 있고
  나머지 여섯은 따로 받습니다. 화면이 뜬 뒤 한가할 때 미리 받아 두어 화면을 옮길 때는
  기다리지 않습니다 (`report/src/App.jsx`).
- 라이브러리를 성격별로 갈랐습니다 (`report/vite.config.js`의 `manualChunks`).
- 등장 연출의 화면 진입 판정을 관찰자 하나로 모았습니다 (`report/src/lib/reveal.js`의
  `whenInView`). Anime.js는 애니메이션만 맡습니다.
- 스크롤을 직접 듣던 곳을 없앴습니다. 스크롤마다 위치를 물으면 그때마다 레이아웃이
  강제로 돕니다 (`report/src/lib/hooks.js`의 `useInView`).

### 다음에 시도해 볼 것

진입 블록의 남은 몫은 대부분 파싱과 컴파일입니다. 아래 순서로 보면 됩니다.

1. 첫 화면이 정말 필요로 하는 것만 남기기. 지금 한눈에 보기는 Bklit 막대 차트를
   그리느라 차트 묶음과 Motion을 처음부터 들고 옵니다. 첫 화면 차트를 가벼운 것으로
   바꾸거나 차트만 나중에 받게 하면 가장 크게 줄어듭니다.
2. `report/src/data/census.json`이 96KB입니다. 화면마다 필요한 부분만 갈라 두면
   첫 화면이 읽는 양이 줄어듭니다. 가르는 자리는 `report/scripts/sync-data.mjs`입니다.
3. 그래도 200밀리초를 못 맞추면, 기준을 못 맞춘 사실과 실측치를 그대로 보고하고
   임의로 대기 시간을 늘리는 대응은 하지 마십시오. 지시받은 원칙입니다.

### 측정 기록 (CPU 4배 느리게, 상황마다 20회)

수정 전, 커밋 `bbb34e6` 기준

- 한눈에 보기 진입: 가장 긴 멈춤 470밀리초, 중앙값 447, 기준 초과 20/20회
- 한눈에 보기 스크롤: 0밀리초, 초과 0/20회
- 성장 단계 스크롤: 0밀리초, 초과 0/20회
- 성장 단계 보정 전환: 0밀리초, 초과 0/20회
- 조사 방법 진입: 가장 긴 멈춤 435밀리초, 중앙값 404, 기준 초과 20/20회

수정 후, 이 커밋 기준 (5회 표본. 20회 반복 측정은 다음에 할 일)

- 한눈에 보기 진입 397밀리초, 중앙값 385, 기준 초과 5/5회 (**아직 미달**)

### 재현되지 않은 것

**보고받은 30초 멈춤은 재현하지 못했습니다.** CPU 4배와 6배 저속 조건에서
스크롤 20회 반복, 보정 전환 클릭, 슬라이더 끌기, 배포본을 실제 창을 띄운 브라우저로
굴리기까지 해봤으나 스크롤과 클릭 구간은 전부 0밀리초였습니다.
잡아서 고친 것은 진입 구간의 블록이고, 그것이 30초 멈춤과 같은 원인인지는
확인되지 않았습니다. 다음에 이어갈 때 본인께 이것부터 여쭤 보십시오.

- 30초 멈춤이 **첫 진입 직후**였는지, **한참 보고 있다가**였는지
- 첫 진입 직후라면 지금 고친 것과 같은 원인일 가능성이 높습니다
- 한참 뒤였다면 다른 것을 찾아야 합니다 (메모리 누수, 관찰자 누적 등)

## 이름과 주소

- 사이트 이름은 **Arad Census**로 되돌렸습니다. 로고, 타이틀, OG 메타, 문서 제목 전부입니다.
- **주소는 `dnf-census.vercel.app`을 정 주소로 씁니다.** 주소는 Vercel 프로젝트
  이름을 따라가는데, 여기서는 Vercel 명령줄 도구도 자격 증명도 없어 프로젝트명을
  되돌릴 수 없었습니다.
- 옛 주소 `arad-census.vercel.app`은 308로 정 주소에 넘겨 보냅니다. 한 주소로 수렴합니다.
- GitHub 저장소도 `dnf-census`이고 `arad-census`는 301로 넘어갑니다.
- **주소까지 되돌리려면** Vercel 대시보드에서 프로젝트 이름을 `arad-census`로 바꾸면
  됩니다. 그 뒤 `report/index.html`의 `og:url`과 `og:image`,
  `report/scripts/check_prod.mjs`의 기본 주소, `README.md`, `docs/quality.md`를
  새 주소로 바꾸십시오.

### 이름이 바뀌었던 경위

지시받은 적 없는 변경이 맞습니다. 커밋 `9de35d4`(2026년 8월 31일 08:58,
다른 세션)에서 "프로젝트명 Arad Census -> DNF Census 통일"로 저장소, Vercel
프로젝트, 문서, 화면 이름을 한꺼번에 바꿨습니다. 커밋 메시지에 이름 충돌 같은
외부 사정은 적혀 있지 않고, 스스로 통일하겠다고 판단한 것으로 보입니다.

## 이번 판에서 알아 둘 것

### 다시 만들 수 없는 것 두 가지

개인정보 방침에 따라 원본 표본(`data/checkpoints/`)을 이미 폐기해서
2차 기준으로는 계산할 수 없습니다. 그래서 화면에서 걷어냈습니다.

- 성장 단계 화면 하단의 명성 히스토그램. 1만 단위로 세려면 원본 명성값이 필요합니다.
  그 자리는 상한 보정 근거 절로 대체했습니다.
- 직업군 막대 안의 전직 칸. 남녀가 나뉜 직업군은 전직 이름이 같아 집계만으로는
  어느 쪽인지 가릴 수 없습니다. 직업군 크기만 그립니다.

### 실측치 표의 셈법

이번 판 여섯 항목 합계가 18,462회입니다.
처음 조사 커버리지 측정 867, 시드 고르기 867, 커버리지 측정 867, 표본 수집 8,001,
상한 우회 7,200, 활성도 조사 660.
명성 방식 검증 947회와 처음 조사 933회는 이번 판 이전 것이라 별도 줄로 두었고,
모두 합치면 20,342회입니다.

### 문구 규칙

쉬운 말, 줄표 금지, 코드 식별자 금지, 의문형 소제목 금지입니다.
`verify_final.py`가 소제목의 `는가`, `은가`, `인가` 종결을 잡습니다.
그래서 지시받은 탭 이름 "처음 조사와 무엇이 달라졌는가"를
**"처음 조사와 달라진 점"**으로 넣었습니다. 원래 문구를 쓰시려면 되돌리고
검사 규칙에 예외를 두어야 합니다. 본인 판단을 아직 못 받았습니다.

## 자주 쓰는 명령

```bash
# 리포트 빌드와 검수
cd report
npm install
npm run build                  # 집계 파일을 화면 용어로 바꾼 사본을 먼저 만든다
node scripts/build-copy.mjs    # 화면 문구 전문 뽑기
node scripts/capture.mjs       # 캡처와 화면 글 모음
node scripts/stability.mjs     # 표시 안정성 14가지
node scripts/font-check.mjs    # 세리프 글자가 폴백으로 안 떨어지는지
node scripts/check_prod.mjs    # 배포본 확인

# 성능
node scripts/perf-block.mjs 20 4        # 상황별 멈춤, 20회 반복
node scripts/perf-profile.mjs enter-overview 4   # 어느 함수가 잡아먹는지
node scripts/perf-layout.mjs overview 4 200      # 스크롤당 레이아웃 횟수
node scripts/perf-live.mjs https://dnf-census.vercel.app 6   # 배포본을 실제 창으로

# 데이터와 문서 대조
cd ..
python scripts/verify_final.py       # 집계, 화면 숫자, 금지 표현, 표시 안정성
python scripts/verify_findings.py    # 문서 인용 수치와 산출물 대조
python scripts/check_docs_links.py   # 문서 링크와 이미지
```
