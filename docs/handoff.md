### 원인 두 가지와 고친 방법

**하나. 등장 연출이 요소마다 위치를 물어 배치를 강제로 돌리고 있었습니다.**

프로파일에서 자기 시간 353밀리초를 한 함수가 쓰고 있었습니다.
`reveal.js`의 `docTop`, 곧 `getBoundingClientRect`입니다.
등장 연출은 요소가 올라올 때마다 모양을 손대고(투명도와 위치) 곧바로 위치를 물었습니다.
손댄 직후에 물으면 브라우저는 그 자리에서 배치를 다시 계산합니다. 요소 수만큼
되풀이되니 그것만으로 0.35초가 갔습니다.

고친 방법: 위치를 재는 일을 등록할 때가 아니라 실제로 스크롤이 일어난 뒤로 미루고,
잴 것을 한 번에 몰아서 잰 다음 켭니다 (`report/src/lib/reveal.js`).
화면에 걸쳐 있는 요소는 어차피 교차 관찰자가 알려 주므로 잴 일 자체가 없습니다.

**둘. 화면 하나를 한 번에 다 그리고 있었습니다.**

첫 번째를 고치고 나니 남은 비용은 배치 계산 그 자체였습니다. 트레이스로 보니
한 작업 안에서 문서 전체 배치가 한 덩어리로 돌고 있었습니다 (432밀리초).
리포트 한 화면은 세로 3천 픽셀이 넘는데, 눈에 보이는 것은 900픽셀뿐인데도
전부를 한 번에 계산했습니다.

고친 방법: 묶음을 한 프레임에 하나씩 들여보냅니다
(`report/src/lib/admit.js`, `Stagger`가 씁니다). 배치 계산이 묶음 수만큼 잘게
나뉘어 한 번에 붙잡는 시간이 짧아집니다. 전부 들어오기까지 걸리는 시간 자체는
거의 그대로입니다.

곧바로 그리는 묶음을 몇 개 둘지도 재봤습니다. 하나도 두지 않는 쪽이 가장
좋았습니다. 0개면 136밀리초, 1개면 188, 2개면 260, 3개면 241입니다.
제목 묶음 하나만 곧바로 그려도 첫 배치에 제목 글꼴 처리가 함께 걸려 다시
무거워집니다. 사람 눈으로는 한 프레임 차이라 알아볼 수 없습니다.

만들면서 어긋났던 곳 두 가지를 적어 둡니다. 같은 방식을 다시 만들 때 그대로
밟게 되는 자리입니다.

- 차례를 돌리는 일을 자리를 받을 때만 걸어 두면, 기다리겠다는 등록이 들어오기
  전에 차례 돌리기가 끝나 버립니다. 그러면 남은 묶음이 영영 안 들어와 화면이
  제목만 남습니다. 등록하는 자리에서도 다음 차례를 불러야 합니다.
- 그리는 사이에 차례가 지나간 묶음이 생깁니다. 그리기와 등록 사이에 한 프레임이
  끼기 때문입니다. 이것을 그냥 흘려보내면 그 묶음만 빈 채로 남습니다.
  실제로 한눈에 보기에서 카드 한 장과 숫자 한 칸이 빠졌고, 화면 문구 전문을
  대조해서 잡았습니다. 지나간 묶음도 줄을 세워 다음 프레임에 켭니다.

### 재본 뒤 아니라고 판명된 것

같은 조건에서 재보고 원인이 아니라고 확인한 것들입니다. 다시 뒤지지 않도록 남깁니다.

- 자바스크립트 파싱과 컴파일. 앞 회차에서 남은 몫으로 지목했지만 아니었습니다.
  진입 구간의 배치 계산이 몫의 대부분이었습니다.
- 차트. 한눈에 보기에서 차트를 통째로 들어내도 배치 비용이 그대로였습니다.
- 격자와 신축 배치, 아이콘 도형, `word-break`와 `overflow-wrap`.
  각각 무력화해 봤지만 모두 오차 범위였습니다.
- `content-visibility: auto`. 405에서 353밀리초로 조금 줄지만, 화면 밖 내용을
  그리지 않는 방식이라 전문 뽑기와 캡처에 위험이 있어 넣지 않았습니다.
  묶음을 나눠 들여보내는 방식과 겹쳐 써도 248에서 246으로 거의 그대로였습니다.

### 손대지 않은 것 (판단이 필요합니다)

진입 비용에서 지금 가장 큰 몫은 **첫 배치의 글꼴 처리**입니다. 다만 화면 생김새가
걸린 문제라 임의로 바꾸지 않았습니다.

- 이 화면은 글꼴 조각 파일을 36개, 약 1.1메가바이트 받습니다
  (Pretendard 20개, Noto Serif KR 16개). 조각이 하나 도착할 때마다 문서 전체
  배치가 다시 돕니다.
- `@font-face` 규칙이 340개입니다 (Pretendard 92, Noto Serif KR 248).
  같은 조건에서 재보니 규칙 수만으로 첫 배치에 35밀리초가 붙습니다
  (0개 24밀리초, 340개 59밀리초).
- 줄일 방법은 세 갈래입니다. 제목용 세리프의 굵기를 400과 700 둘에서 하나로 줄이거나,
  세리프를 쓰는 글자만 뽑아 조각을 직접 만들거나, `font-display`를 `optional`로 바꿔
  늦게 온 글꼴로 바꿔치기하지 않게 하는 것입니다. 셋 다 화면 생김새가 바뀝니다.
- 글꼴 CSS를 렌더 차단으로 되돌리면 240에서 206밀리초로 줄지만, 바깥 CDN 응답이
  늦으면 첫 그림이 통째로 늦어집니다. 지금 방식(늦게 걸기)을 그대로 두었습니다.

### 재현되지 않은 것

**보고받은 30초 멈춤은 이번에도 재현하지 못했습니다.** 스크롤과 클릭 구간은
CPU 4배와 6배 저속 조건에서 모두 0밀리초입니다. 잡아서 고친 것은 진입 구간이고,
그것이 30초 멈춤과 같은 원인인지는 확인되지 않았습니다.

- 30초 멈춤이 **첫 진입 직후**였는지, **한참 보고 있다가**였는지
- 첫 진입 직후라면 지금 고친 것과 같은 원인일 가능성이 높습니다
- 한참 뒤였다면 다른 것을 찾아야 합니다 (메모리 누수, 관찰자 누적 등)

## 이번 판에서 알아 둘 것

### 다시 만들 수 없는 것 두 가지

개인정보 방침에 따라 원본 표본(`data/checkpoints/`)을 이미 폐기해서
2차 기준으로는 계산할 수 없습니다. 그래서 화면에서 걷어냈습니다.

- 성장 단계 화면 하단의 명성 히스토그램. 1만 단위로 세려면 원본 명성값이 필요합니다.
  그 자리는 상한 보정 근거 절로 대체했습니다.
- 직업군 막대 안의 전직 칸. 남녀가 나뉜 직업군은 전직 이름이 같아 집계만으로는
  어느 쪽인지 가릴 수 없습니다. 직업군 크기만 그립니다.

### 실측치 표의 셈법

이번 판 여섯 항목 합계가 18,462회입니다.
처음 조사 커버리지 측정 867, 시드 고르기 867, 커버리지 측정 867, 표본 수집 8,001,
상한 우회 7,200, 활성도 조사 660.
명성 방식 검증 947회와 처음 조사 933회는 이번 판 이전 것이라 별도 줄로 두었고,
모두 합치면 20,342회입니다.

### 문구 규칙

쉬운 말, 줄표 금지, 코드 식별자 금지, 의문형 소제목 금지입니다.
`verify_final.py`가 소제목의 `는가`, `은가`, `인가` 종결을 잡습니다.
그래서 지시받은 탭 이름 "처음 조사와 무엇이 달라졌는가"를
**"처음 조사와 달라진 점"**으로 넣었습니다. 원래 문구를 쓰시려면 되돌리고
검사 규칙에 예외를 두어야 합니다. 본인 판단을 아직 못 받았습니다.

## 자주 쓰는 명령

```bash
# 리포트 빌드와 검수
cd report
npm install
npm run build                  # 집계 파일을 화면 용어로 바꾼 사본을 먼저 만든다
node scripts/build-copy.mjs    # 화면 문구 전문 뽑기
node scripts/capture.mjs       # 캡처와 화면 글 모음
node scripts/stability.mjs     # 표시 안정성 14가지
node scripts/font-check.mjs    # 세리프 글자가 폴백으로 안 떨어지는지
node scripts/check_prod.mjs    # 배포본 확인

# 성능
node scripts/perf-block.mjs 20 4        # 상황별 멈춤, 20회 반복
node scripts/perf-profile.mjs enter-overview 4   # 어느 함수가 잡아먹는지
node scripts/perf-layout.mjs overview 4 200      # 스크롤당 레이아웃 횟수
node scripts/perf-live.mjs https://dnf-census.vercel.app 6   # 배포본을 실제 창으로

# 데이터와 문서 대조
cd ..
python scripts/verify_final.py       # 집계, 화면 숫자, 금지 표현, 표시 안정성
python scripts/verify_findings.py    # 문서 인용 수치와 산출물 대조
python scripts/check_docs_links.py   # 문서 링크와 이미지
```
